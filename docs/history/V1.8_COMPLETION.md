## What v1.8 fixed

v1.7's acceptance run reported success while substantive content vanished
silently. v1.8 makes four defects structurally impossible rather than
reviewer-checkable:

| Defect | v1.7 behaviour | v1.8 fix |
|---|---|---|
| Renderer silent drop | Non-numbered H2 sections (`v1.7 Control State`, `Original Submission`, `v1.7 Inference Controls`) were discarded; 29 tables and 23 bullets disappeared into an "apparently successful" PDF | Pre-render **contract linter** validates the Markdown AST before any HTML is produced; **node accounting** cross-checks every source semantic node against the rendered output. Both raise `RenderContractFailure`. |
| BLOCKED == EXHAUSTED | A transient rate limit collapsed into the same terminal bucket as genuine exhaustion, so "we stopped searching" was reported as "the evidence indicates absence" | **Failure-class state machine** separates `TRANSIENT_FAILURE → RETRY → FALLBACK` from `EPISTEMIC_EXHAUSTION`. An avenue cannot become EXHAUSTED while an admissible recovery path remains unattempted. |
| Coverage substitutions | Single source accepted where ≥2 required; Crossref for a domain source; NAICS code for a bounded market model; candidate list for a partner-fit analysis; partial cited-reference set; skipped orientation stage | **Coverage gates** (machine-enforceable per-avenue rules with required sources, aliases, minimum attempts, and required schema fields) feed the compiler and are reported in `coverage-report.json`. |
| Text-only QA | `pdftotext` verified text presence, not visual correctness | **Structural + visual QA gate**: rasterizes the eight critical pages (cover, executive summary, technology profile, SWOT, claim mapping, operational audit, chart-heavy page, final page) and inspects for clipping, overlaps, page breaks, footer collisions, and blank pages. Both gates must pass. |

## v1.8 presentation re-skin

The Retinal Prosthesis report was previously rendered as a raw engineering
diligence file (flat Markdown, evidence registers, YAML blocks, data dumps).
The presentation layer was re-skinned to match the client-ready sample's
structure **without removing a single piece of analytical content**:

- **Six full-bleed divider pages** (TECHNOLOGY ANALYSIS, PATENT LANDSCAPE
  ANALYSIS, NOVELTY & INTELLECTUAL PROPERTY ANALYSIS, LITERATURE ANALYSIS,
  MARKET ANALYSIS, POTENTIAL PARTNERS) — the sample's signature layout.
- **Running header** on every printed page:
  `IEAUS8527057: Retinal Prosthesis – Patent Analysis`.
- **Appendices A–D** relocating the raw material so the main narrative stays
  readable:
  - A. Patent Family & Legal Status (rights state, expiration, assignments)
  - B. Search Methodology & Claim-Domain Vectors
  - C. Evidence Debt & Recovery Queue (P-05-001, P-05-002, P-07-001, P-08-001)
  - D. Proposition Register (all P-codes)
- **SWOT** rendered as the sample's 2×2 grid with the
  `Commercial Actionability / Indeterminate-to-Limited` badge.
- **Charts** from the scores manifest: region pie, applicants pie, activity
  line, NAICS dual-axis, employee-size brackets.

The report is 43 pages. Every claim map, evidence debt item, data point,
causal-bridge YAML block, and proposition ID is preserved — it is relocated,
not summarised. The contract linter and visual QA gate both pass on the
re-skinned output.

## Known limitations

Domain adapters remain intentionally conservative. Claim-level anticipation,
literature relevance, market sizing/adoption, and organization-specific
partner fit remain `WORK QUEUE` until their required schema fields and
proposition-level support are present. These are evidence limitations, not
pipeline failures.

## Version boundary

v1.8 hardens the control, coverage, rendering, and verification layers. The
next step is v1.9: deeper domain-specific interpretation, broader source
coverage, ranking improvements, and specialized legal/market analysis.
